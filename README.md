# CreditScoreV4 ML Governance

**Production ML Incident Simulation, Remediation & Governance**

CreditScoreV4 ML Governance is a production-style case study built around one continuous ML failure lifecycle. Phase 1 reproduces a vendor-induced model degradation, Phase 2 adds blocking data-quality governance, Phase 3 detects contract-valid statistical drift, and Phase 4 adds subgroup fairness assessment plus SHAP explainability.

## Continuous incident story

```text
Healthy Vendor A
  device_risk_score NULL ≈ 3%
        |
        +--> CreditScoreV4 baseline ROC-AUC ≈ 0.80
        |
        +--> Vendor B migration
        |      device_risk_score NULL ≈ 22%
        |              |
        |              +--> same model ROC-AUC ≈ 0.73
        |              +--> Phase 2 quality gate --> BLOCK / quarantine
        |
        +--> Vendor C contract-valid shift
               schema / types / ranges / NULL limits still valid
                        |
                        +--> Phase 2 quality gate --> PASS
                        |
                        +--> feature PSI + KS
                        +--> prediction PSI + KS
                        +--> overall drift --> CRITICAL
```


Phase 4 adds a separate Vendor D fixture in which only a synthetic evaluation subgroup receives moderate shifts in non-protected risk proxies. The batch remains contract-valid and aggregate-STABLE under Phase 3, allowing subgroup fairness and SHAP controls to demonstrate a distinct governance failure mode.

Measured values are generated by the verification commands; they are not hard-coded production claims.

## Quick start

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
make phase4-verify
```

A successful Phase 4 release gate proves that Vendor D passes Phase 2, remains aggregate-STABLE under Phase 3, yet fails configured subgroup fairness governance and produces SHAP evidence for the non-protected proxy drivers.

## Scope boundary

Phase 4 assesses and explains synthetic subgroup disparities. Its thresholds are configurable project governance controls, not legal conclusions or proof of regulatory compliance. Mitigation/retraining, model registry and promotion policy, serving, observability, and cloud automation remain intentionally deferred to later phases.
